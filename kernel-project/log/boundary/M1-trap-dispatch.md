# M1 trap 分发边界

## 目标

让两个架构保存的 `TrapContext` 统一进入 `kernel/trap.rs`，接通用户系统调用的参数提取、分发、返回值写回和返回 PC 推进。

## 非目标

- 不创建 Task、用户地址空间、用户栈或每任务内核栈。
- 不处理时钟、外部或核间中断。
- 不实现缺页按需分配、信号、调试器或异常恢复。
- 不开启任何中断，也不主动进入用户态。

## Owner 与 Handoff

- `arch/*/trap` 拥有寄存器保存 ABI、硬件异常号解码和寄存器读写。
- `kernel/trap.rs` 拥有架构无关的分发和失败策略。
- `kernel/syscall` 拥有系统调用号、参数语义和 errno。

当前汇编入口仍使用 trap 前的当前栈。用户态执行必须等任务模块能够在 trap 时切换到可信内核栈后再启用。

## Failure / Cleanup

只有用户态 syscall 可恢复返回；内核态 syscall、页错误、中断及其他异常均打印现场并停机，避免重复执行故障指令或在不可信现场继续运行。

## 验收与验证

- `make all` 双架构通过。
- 静态确认 RISC-V64 `a7/a0..a5/a0` 与 LoongArch64 `a7/a0..a5/a0` 的系统调用寄存器映射。
- 静态确认返回 PC 在分发前增加 4 字节。
- 不启动 QEMU；当前也没有合法的用户态入口可做运行期 syscall 测试。
