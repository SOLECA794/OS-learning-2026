# Boundary: M1.5 用户态首闭环（2026-10-12）

- 日期：2026-10-12
- 类型：设计评审 + Implementation Boundary（W1 第 7 项落地；规划书 W2 的前提）
- 依据：2026-10-12 规划书 W2（RV 用户态、内核栈、静态 ELF、write/exit）+ 治理裁决
  （用户态主线先行、LA 接口同步设计功能后置、build-only/runtime 如实区分）

## 目标（W2 验收）

RV QEMU 上：内核初始化 → 进入用户态 → 用户程序 `write(1, "hello from user mode")`
→ `exit(0)` → 内核记录退出并停机。附加验收：错误指针（NULL / 内核地址）受控返回
EFAULT，用户态不能访问内核保护区（U=0 缺页被捕获为受控失败）。

## 接口与设计决策（评审结论）

### 1. trap 用户态/内核态切换（RV）
- `sscratch` 协议：用户态运行时 `sscratch = 当前任务内核栈顶`，内核态运行时
  `sscratch = 0`。
- 进入：`csrrw sp, sscratch, sp` 交换；`sp != 0` → 来自用户态（sp=内核栈顶），
  `sp == 0` → 内核态（换回）。统一在 sstatus.SPP 判断来源以设置 x2 槽
  （x2 = trap 前 sp：用户态=用户 sp，内核态=内核 sp）。
- 返回：恢复寄存器后按 SPP 决定是否把 `sscratch` 重置为内核栈顶（用户态返回必须，
  内核态返回必须保持 0，否则下次内核态 trap 被误判为用户态）。
- 恢复段抽为独立符号 `__riscv64_trap_restore`：既是 trap 返回路径，也是
  "从构造好的 TrapContext 进入用户态"（初始化流程复用）。
- 单层现场：M1.5 无中断、无用户态 page-fault 恢复，trap 处理中不会嵌套。

### 2. 用户地址空间
- 布局（RV sv39）：内核映射（复用 new_kernel 区域）+ 用户 TEXT/RODATA/DATA/BSS
  @0x10000（uapp 链接基址）+ 用户栈（单页，@0x8000_0000 向下）。
- 0 页不映射：NULL 解引用 → 缺页 → 受控失败（"错误指针受控"）。
- 用户页表 = 内核映射 + 用户段：用户态访问内核区（U=0）→ 缺页受控。

### 3. ELF 加载器（自研最小）
- 仅解析 ELF64 ehdr + program headers；只处理 LOAD 段（p_type=1）。
- 按 p_vaddr 页对齐映射；filesz 内容拷贝，memsz-filesz 清零（BSS）。
- 拒绝：非 ELF、非 RV64、段越界、vaddr 与内核/栈区重叠。
- 位置：`src/kernel/elf.rs`，无第三方依赖（治理裁决：最小依赖）。

### 4. uaccess（用户内存访问）
- `copy_from_user(dst, src_user, len)`：校验 `src_user..src_user+len` 落在用户段
  （>= USER_TEXT_BASE 且 < USER_SPACE_TOP，且非 0 页），失败返回 EFAULT。
- M1.5 不做逐页 PTE 权限查询（单任务、无 fork），以段边界校验为准；
  M1.6（多任务）换为逐页校验。

### 5. syscall（新增 write/exit）
- `write(fd, buf, len)`：fd=1 → copy_from_user → console 输出 → 返回 len；
  fd 非法 → EBADF；buf 非法 → EFAULT。不缓冲，直接输出。
- `exit(code)`：打印用户退出码 → 停机（M1.5 单任务无调度；M3 换为回收+调度）。
- 未知 syscall 保持 ENOSYS（现有行为）。

### 6. uapp（用户程序）
- 独立 crate `user/`：Rust no_std + no_main，`_start` 内联汇编 ecall syscall。
- 链接基址 0x10000（user/user.ld）。构建：`make user` 前置产出
  `build/user/uapp.elf`；内核 `include_bytes!("../build/user/uapp.elf")`。
- 内容：write(1, "hello from user mode\n") → exit(0)。

## 不做（边界外，登记为限制）

- LA 用户态功能（接口同构设计，RV 验证通过后再移植）。
- 调度器 / 多任务 / fork / COW（M3 起）。
- 中断（timer）与用户态 page-fault 恢复（fatal 即可）。
- 动态链接 / libc / 文件系统（W5 起）。

## 验收（agent-run）

1. RV `make build` + `make test`：日志含用户程序输出与 exit 记录。
2. 构造错误指针用例（可选：uapp 变体）验证 EFAULT 路径。
3. LA `make build` 保持通过（接口未破坏）。

## 实现顺序

1. user/ uapp + user.ld + Makefile 集成（include_bytes 依赖）
2. arch/riscv64/trap/entry.rs：sscratch 切换 + 抽 restore 符号
3. arch/riscv64/trap/context.rs：用户进入构造器
4. src/kernel/elf.rs：最小 ELF 加载
5. kernel/mm：用户地址空间（new_user）
6. kernel/syscall：write/exit + copy_from_user
7. kernel/mod.rs：init 用户进程流程
8. WSL 验证 + change record

## Friction Scan 预登记

- 风险：include_bytes 使 kernel 编译依赖 user 构建产物（顺序耦合）——Makefile 强制
  依赖；`cargo check` 同样前置（已知限制，登记 docs/07）。
- 风险：x2 槽语义从"trap 前 sp"扩展到含用户 sp——entry/restore 汇编与 context.rs
  的 16(sp) 偏移契约不变，仅写入值语义扩展（无 ABI 变化）。
