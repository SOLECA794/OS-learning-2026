## 变更

### P0① 多核重复清 BSS 竞态（规划书 W1 第 2 项）

原实现：每核进内核先清 BSS，再经 `.data` 的 BOOT_LOCK 选主——迟到核可能在主核
初始化全局后再次清零，重置状态（条件性竞态）。

修复：**汇编不再清 BSS**；所有核进入 `kernel_main` 时 BSS 未清，先由 BOOT_LOCK
（`.data`，不依赖 BSS）选主；唯一主核调用新增 `clear_bss()`（volatile 写 + Release
fence）后再进入主流程；从核不清 BSS、直接停驻。

验证：
- RV `-smp 4` 实测主核为 **hartid=1**（非 hart 0），选主→清 BSS→mm::init→M1 标记
  全链路正常——证明协议不假设"固件先引导 hart 0"。
- 从核在 BSS 未清状态下执行 swap/park 无 panic（QEMU 正常跑至停机）。
- LA 同协议，M1 标记正常。

### P0② LoongArch CSRWR 汇编约束错误（规划书 W1 第 3 项）

原实现：`csrwr {page_shift}, 0x1e` + `csrwr {page_shift}, 0x8e`，全部操作数声明
`in(reg)`。CSRWR 会把旧 CSR 值写回源寄存器：第一次写后 page_shift 已被污染，
第二次写入的不是 12；且 `in(reg)` 约束要求输入寄存器保持原值，均违反契约。

修复：所有被 CSRWR/CSRXCHG 覆盖的操作数改为 `inlateout(reg) x => _`；
两个页大小 CSR 各用独立寄存器装载 12（ps/ps2），第二次写入不依赖被污染的寄存器；
crmd_mask 不被 csrxchg 修改，保留 `in(reg)`。

验证：LA `make build` + QEMU 至 M1 标记（分页激活 + heap 正常）。
残留：未逐条反汇编核实 CSR 写入序列（QEMU 运行通过为间接证据，M1.5 前补反汇编核对）。

### P1③ Make 编排契约（规划书 W1 第 4 项）

原问题：`make ARCH=<arch> defconfig clean build` 组合命令会跳过 build.mk 导出并
删除刚生成的配置（make -n 已复现空 mkdir/cp）。

修复：Makefile 增加编排契约检查——goals 同时含配置/清理目标与构建目标时直接
`$(error)` 报错并提示分步命令；README 已改三次独立调用。

### P1④ kconfig `_Evaluator` 属性引用（规划书 W1 第 5 项）

原 bug：`_Evaluator._atom` 引用 `self.symbols`（该属性不存在），条件表达式求值
AttributeError；默认 defconfig 未走该分支故未暴露。

修复：`self.symbols` → `self.menu.symbols`（真相源在 Menu）。
menuconfig 仍未实现：保持"提示并返回失败"，已登记为已知限制（docs/07）。

### W1 第 6 项：make test 最小运行入口

新增 `scripts/run-test.sh`：在当前已配置架构上启动 QEMU，超时 60s、grep M1 标记、
退出码 0/1、原始日志留 `build/test-<arch>.log`。Makefile `test` 目标委托该脚本
（依赖 QEMU 与 bash，开发环境 = WSL）。

验证：RV/LA 各跑 `make test` → PASS（rc=0）。
