## 问题与根因

- 现象/需求：仓库此前只有治理与设计文档（`docs/`），没有任何可构建代码。M0 要求「规范落地、Rust 工具链、双架构 boot、最小内核」。
- 根因（非显然时）：
  - 本机没有 `make`、没有 QEMU、没有交叉 target —— 工具链本身是 M0 的一部分工作量，不是环境前提。
  - `sdd-governance/AGENTS.md` 模板写的是 `src/utils/`，而 `docs/01-architecture.md` 写的是 `src/klib/` —— 两处对同一个模块的命名不一致。
- 被违反的不变量 / ABI 规则 / 状态所有权规则：无（本次是首个 contract，此前无契约可违反）。

### 语义级

1. **构建链贯通**：Kconfig（bool/choice → Cargo feature；int/string → 脚本变量，符合 docs/07 §2「QEMU 启动值走脚本而非 feature」）→ `config/config.mk` → `build.mk` → Cargo feature / QEMU 参数。
2. **架构选择单一真相源**：`ARCH` 由 `config/.config` 反推，命令行传入的 `ARCH` 只做一致性校验，不一致直接 `$(error)`。
3. **双架构 boot**：`_start`（汇编）→ 清 BSS → `kernel_main(hartid, dtb_pa)` → 串口 → banner → 停机。
4. **klib 不反向依赖 arch**：字节输出走链接期符号 `kernel_arch_console_write`，klib 源码里不出现 `crate::arch` 路径。

### 决策与理由

| 决策 | 选择 | 不这样选的理由 |
|---|---|---|
| Kconfig 解析 | 自研 `tools/kconfig.py`（零第三方依赖，约 300 行） | kconfiglib 要走 pip + Windows 还需 windows-curses；docs/00 §5「最小依赖」与 docs/07 §4「离线可复现」优先 |
| 模块目录 | `src/klib/`（依 docs/01 §5） | AGENTS.md 模板的 `src/utils/` 是通用占位；已在仓库 AGENTS.md 里显式标注这一分歧 |
| 架构分支判断 | `cfg(feature = "arch-*")`，不用 `cfg(target_arch)` | feature 才是构建链的真相源，避免两处判断架构 |
| 日志输出 | klib 声明 `extern "C"` 钩子，arch 提供 `#[no_mangle]` 实现 | 直接 `klib → arch` 会违反「上层依赖下层」；注意该钩子在架构**未实现**时才产生链接期错误，实现后可能被内联（符号表里看不到），不要据此判断"没接上" |
| M0 是否启用分页 | 不启用（RV: 无 SATP；LA: CRMD.DA=1 物理直址） | 页表属 docs/01 §4 的 `mm::init`，是 M1 内容 |
| boot 栈 | 只给 bootstrap hart 一个 64KB 栈，secondary hart 在汇编里 park | M0 没有 per-hart 栈/IPI/调度器；已注明退出条件 |
| `make test` | 明确报错退出（exit 1）而不是"假装通过" | docs/10：用户态测例随 M1 的 init 进程接入；伪造通过违反验证伦理 |

### 兼容/ABI 取舍

- `kernel::main(hartid, dtb_pa)`：LoongArch 的 `-kernel` 入口不通过寄存器传 DTB，该架构下 `dtb_pa = 0`，语义是「未提供」。已在函数文档与 banner 输出中写明，属于未闭合的 arch handoff（M1 统一为「先探测固件传参，再回落到固定位置」）。

### 临时桥 / 退出条件

| 临时做法 | 保留原因 | 移除条件 |
|---|---|---|
| secondary hart 在汇编里 `wfi` / `idle` 停机 | M0 无 per-hart 栈、无 IPI、无调度器 | M1 落地 `arch::setup_all_cores` |
| RV 用 legacy SBI console_putchar（EID 0x01） | 所有 OpenSBI 版本都支持，boot 早期无需探测扩展 | M1 引入统一 SBI 封装后改为优先 DBCN |
| LA 波特率除数写 1 | QEMU 不按真实时钟采样 | M4 上实板时按真实 UART 时钟重算 |
| 单条日志 512 字节栈上缓冲，超长截断 | 内核早期无堆 | M1 kalloc 落地后改为分片输出 |
| `arch::<arch>::LINK_BASE` 常量 | 仅服务日志 | M1 改为从内核符号表读取 |

- 失败集 diff：无既有失败集（首次构建）。
- 残余风险与下一步最小验证（按优先级）：
  1. **LoongArch 运行时未验证。** 最大不确定点是 DA=1 下 UART MMIO 的访存属性（`CRMD.DATM/DATF` 未在 boot 汇编里显式设置，依赖 QEMU reset 状态）。M1 建立 DMW/页表时会显式设定。
  2. **BSS 当前为空**（没有 `static mut`），清零循环未被运行时真正检验；M1 引入静态结构后才有实际覆盖。
  3. **RV 依赖 OpenSBI 支持 legacy console_putchar**；若固件精简过会无输出。
  4. `dtb_pa` 在 LA 恒为 0，尚未接入 FDT 解析。

  用户侧最小验证（两个架构各一条）：

  ```bash
  cd kernel-project
  python tools/kconfig.py --defconfig config/defconfig-riscv64 && make run
  python tools/kconfig.py --defconfig config/defconfig-loongarch64 && make run
  ```

  预期信号：串口出现 `M0 boot OK`（docs/09 §5 要求输出可 grep）；LA 侧若**无任何输出**，
  优先怀疑 UART 访存属性而不是链接地址（地址已由 `check-image.py` 机械校验过）。

## 收口检查（Architecture Friction Scan）

- 第二份真相源：
  - **已消除**：`ARCH`（make 命令行变量）与 Kconfig 的 `choice 目标架构` 曾并存 → 现由 `config/.config` 反推 ARCH，命令行只做一致性校验。
  - **已登记（Euclid）**：链接基址有三处表述 —— `linker/<arch>.ld` 的 `BASE_ADDRESS`（真相源）、`build.mk` 的 `LINK_BASE`（被 `check-image.py` 机械校验）、`arch::<arch>::LINK_BASE`（仅日志用，无校验）。最小修正方向：M1 改为从内核符号表读取，删掉 Rust 常量。
- owner 穿透：无。`klib` 源码中不出现 `crate::arch` 路径（可用 grep `src/klib -r "crate::arch"` 回归检查，当前为空）。
- 无退出条件的临时桥：无。上表 5 项临时做法均已写明保留原因与移除条件。
- 扩大 public API：无。`arch` 后端模块保持私有，只 re-export `console / park / ARCH_NAME / LINK_BASE` 四项。
- 降低 ABI/验证诚实性：无。QEMU 运行标 `not-run`；`make test` 在 M0 明确失败而非伪造通过；`make run` 缺 QEMU 时报错退出。
- 结论：**Safe**（1 项 Euclid 已登记，不影响 M0 收口）
