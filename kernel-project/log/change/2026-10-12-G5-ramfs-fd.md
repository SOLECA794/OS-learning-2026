# G5：ramfs + FD 表 + open/close/read/write/dup + fork 共享偏移

日期：2026-10-12
依据：V2 总路线 §9「文件系统与 FD」合同：open/dup/close FD 表；打开文件对象持偏移与
内容引用；错误 FD→errno；最后引用释放与进程退出清理一致；路径/文件内容/打开偏移
各只有一个权威来源；不抽象 VFS，先具体 enum。
前置：G4 exec（bacbd67）——程序源已从静态表迁至 ramfs。

## 实现

- **`src/kernel/fs/file.rs`**：`OpenFileDesc{name, offset:AtomicUsize, readable, writable}`
  ——打开文件对象（dup/fork 共享的偏移唯一权威单元）；`FdEntry` 具体 enum
  `{Console, File(Arc<OpenFileDesc>)}`（不抽象 VFS，V2 §9）；`FdTable` = Vec<Option<FdEntry>>，
  new() 置 fd0/1/2=Console，alloc 复用最小空槽，close 置 None；`#[derive(Clone)]`
  走 Arc clone → fork/dup 共享偏移。
- **`src/kernel/fs/ramfs.rs`**：全局 `RAMFS: SpinLock<RamFs>` 扁平文件列表（内容唯一权威）。
  `init()` 从 programs 表装载 uapp/uapp2/bad + 验收文件 hello.txt/dup.txt/fork.txt；
  `read_file_by_path`（exec 用，去前导 '/' 精确匹配）；`open(name,flags)` 支持
  O_RDONLY/WRONLY/RDWR/CREAT/TRUNC，非法位组合 → EINVAL；`read_at`/`write_at`
  以 desc 自身 offset 为权威（Relaxed 原子读写），越界扩展内容；`list_names`/`exists`（shell 用）。
- **`src/kernel/fs/mod.rs`**：file/programs/ramfs 三 mod + `init()` 调 ramfs::init。
- **`src/kernel/task/mod.rs`**：TCB 增 `fds: FdTable`；create_task 初始化；fork 复制
  `parent.fds.clone()`（共享偏移）；boot_tasks 调 `fs::init()`；新增
  `with_current_fds(闭包)`（持有 SCHED 锁，闭包内禁再取锁）与 `current_pid()`。
- **`src/kernel/syscall/fd.rs`**：sys_openat/sys_close/sys_read/sys_write/sys_dup。
  fd0 read=EOF(0)；非法 fd→EBADF；路径/缓冲全部段校验；write 迁移自旧私有实现
  （fd1/2 控制台 + 文件写）。
- **`src/kernel/syscall/mod.rs`**：新增常量 DUP/OPENAT/CLOSE/READ；fd mod + 分发；
  删旧私有 sys_write；新增 `pub(crate) copy_cstring_from_user`（exec/fd 共用）。
- **`src/kernel/syscall/exec.rs`**：程序源权威迁至 `ramfs::read_file_by_path`
  （读回 Vec<u8> 再 ELF 解析）；本地 cstring 拷贝改调 super::。
- **用户侧**：uapp 新增 F1–F6 验收段（open+read+close / ENOENT / O_CREAT 写读回 /
  EBADF / dup 共享偏移 / fork 共享偏移顺序无关验收），syscall 常量 +6。

## 过程中修掉的真问题

1. **copy_cstring_from_user 栈顶越界**（G5 F1 实机发现）：一次拷满 max_len 时，
   用户栈顶附近的字符串 src+max_len 越出 USER_STACK_TOP → 误报 EFAULT。
   改为「可用区间 = min(max_len, STACK_TOP-src)」一次段校验；区间内无 null 视为超长。
2. **ramfs::open 缺去前导 '/'**（G5 F1 实机发现）：read_file_by_path 有 trim 而 open 没有，
   open("/hello.txt") 查 "hello.txt" 失败 → 误报 ENOENT。补齐 skip_while trim。
3. **两处编译错误**：`ok_or(-22)?` i32→isize（改 EINVAL 常量）；
   `name` 在 None 分支 move 后又用于 OpenFileDesc（改 name.clone()）。

## 设计说明

- **偏移唯一权威**：共享偏移放在 OpenFileDesc（Arc 共享），FD 表只持引用。dup/fork
  复制 FD 表 = 复制引用，偏移天然共享；read/write 用 Relaxed 原子读改写（单核当前
  无竞争，SMP 后需升级）。
- **FD 表不抽象 VFS**：FdEntry 是具体 enum（Console/File），符合 V2 §9「先具体后抽象」；
  未来加设备再扩 enum 变体，不提前建 trait 体系。
- **errno 语义**：read fd=0 → EOF(0)（Linux 行为：无输入可读）；非法 fd → EBADF；
  权限不符（只读 fd 上写）→ EACCES；路径非法 → ENOENT/EINVAL。fd0=Console 但输入
  未实现，read 恒 EOF。
- **程序源迁移**：G4 的静态 lookup 由 ramfs 接管，programs.rs 降为 boot 装载表
  （仍内嵌 include_bytes），exec 路径与用户文件路径统一走 ramfs。

## 残留风险

- **O_APPEND 被放行但无语义**（flags 校验放行 0x400，write_at 恒写 desc 偏移，
  不强制文件尾）——shell/测试勿依赖 O_APPEND；登记待 G6 语义化或改 EINVAL 拒绝。
- **fd0 read 恒 EOF**：控制台输入（读 stdin）未实现，符合 V2 §9 G5 范围（先写后读）。
- **共享偏移原子性**：Relaxed + 单核够用；多核并发 read/write 同一 desc 需要
  RMW/锁升级（SMP 阶段）。
- **fs 模块无 cfg**：LA 编译通过但 fd syscall 分发 RV-only；LA 用户态仍 ENOSYS。

## Architecture Friction Scan

Safe：无阻断摩擦。
Euclid（记录不修）：`with_current_fds` 持 SCHED 锁执行任意闭包，调用方误用可死锁；
   当前仅 syscall 层使用且闭包短小，注释已登记约束。`current_pid` 暂无用（shell 阶段启用）。
