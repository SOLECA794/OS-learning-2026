# LoongArch 首批用户态文件 FD 接入

- 日期：2026-10-15；分类：小迭代；关联边界：`log/boundary/LA-M25-file-fd.md`；验证者：agent-run。

## 问题与改动

LoongArch 已共用 TCB 与 VFS，但文件 syscall 分发仍只对 RISC-V 开启，因此用户态不能按路径读文件。现把现有 `openat/read/close` 分发给 LoongArch；文件描述、偏移与路径仍由公共 FD 表和 `kernel/fs` 唯一管理。LoongArch 原 `write` 控制台桥保持不变。

控制台输入尚无 LoongArch RX 中断唤醒：架构层提供轮询读取和「可否安全阻塞」标志；公共读路径在无数据且无唤醒机制时返回 `EAGAIN`，不把任务放入永远不会唤醒的队列。移除条件是 LoongArch 串口 RX 中断与等待者唤醒路径落地。本次未对控制台 stdin 实际输入做运行验收。

## 验证

| 架构 | 比赛镜像命令 | 结果 |
|---|---|---|
| LoongArch | `make ARCH=loongarch64 test-la-file RUN_ID=20261015-la-file-a` | PASS：`LA_FILE_PASS`、退出 0 |
| LoongArch | `test-la-exec RUN_ID=20261015-la-file-exec-regress` | PASS |
| LoongArch | `test-la-process RUN_ID=20261015-la-file-process-regress` | PASS |
| RISC-V | `test-vfs RUN_ID=20261015-la-file-rv-vfs` | PASS |
| RISC-V | `test-console RUN_ID=20261015-la-file-rv-console` | PASS |

原生用户程序检查 `/hello.txt` 和 `/static/readme`、EOF、关闭后 EBADF、缺失路径 ENOENT，以及无效 read 缓冲 EFAULT 后文件偏移不变。它只在全部断言通过后输出 `LA_FILE_PASS`。

## 收口边界

无第二份 VFS/FD 状态；只扩展已存在的 Linux syscall 分发，不改编号或参数布局。LoongArch 的 `write`、`lseek/pread/fstat/getdents`、目录 fd 相对路径和时钟抢占尚未随本次一起验收。低地址用户栈仍是已知临时布局。
