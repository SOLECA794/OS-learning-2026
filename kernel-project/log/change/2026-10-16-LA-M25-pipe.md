# LoongArch pipe 与 stdout 重定向接入

- 日期：2026-10-16；分类：小迭代；关联边界：`log/boundary/LA-M25-pipe.md`。

LoongArch 复用公共 `pipe` syscall。原 fd 1/2 仍指向控制台时保留已有输出桥；
被 `dup2` 重定向后按 FD 表交给公共写路径，避免把管道数据误送串口。
公共 `pipe` 先准备完整 8 字节用户输出缓冲，再分配读写 FD；第二次分配或写回失败时
关闭已分配的槽。原生用户程序先用无效指针验证 EFAULT 无 FD 泄漏，随后验证管道
读写、stdout 重定向及恢复。

## 验证

- agent-run：比赛镜像 LoongArch `test-la-pipe RUN_ID=20261016-la-pipe-a` PASS，`LA_PIPE_PASS` 和最终退出 0。
- agent-run：LoongArch `test-la-dir RUN_ID=20261016-la-pipe-dir-regress` PASS。
- agent-run：RISC-V `test-pipe RUN_ID=20261016-la-pipe-rv-regress` PASS，串口见 `P1P2P3 PIPE-PASS` 且无 `FAIL`。
- agent-run：`make ARCH=loongarch64 fmt-check` PASS；`git diff --check` 收口时复核。

## 剩余边界

`pipe` 仍是固定环形缓冲、非阻塞/无 SIGPIPE 的阶段实现；fd 0 的写入桥、
时钟抢占、高地址用户栈及完整 Linux FD ABI 未完成。

## 架构摩擦扫描

FD 槽仍由 task 唯一持有，管道数据仍由 fs 唯一持有；没有新增第二份状态。
临时桥位于 syscall 分发，仅检查 FD 类型，移除条件写在函数注释中。
