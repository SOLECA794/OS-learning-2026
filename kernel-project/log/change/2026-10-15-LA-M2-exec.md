# LoongArch execve 接入记录

- 日期：2026-10-15；分类：小迭代；关联 Boundary：`log/boundary/LA-M2-exec.md`。
- 涉及：`kernel::syscall::exec`、LoongArch trap 现场、原生用户测试；验证者：agent-run。

## 问题与改动

公共 exec 原先只在 RISC-V 启用，并把新用户栈写死为 RISC-V 地址。LoongArch 的 syscall 现场缺少 `argc/argv` 构造入口。现在 exec 使用架构给出的首任务栈布局，两个架构共用同一实现；LoongArch 仅补充寄存器现场构造。成功时仍一次性替换地址空间；失败时旧地址空间不变。

原生测试先对缺失路径检查 `ENOENT` 和旧现场继续运行，再对 `/la-exec-target` 执行成功路径；目标检查 `argc=1`、`argv[0]="check"` 与空结尾，输出 `LA_EXEC_PASS` 后退出 0。测试 ELF 中多个本地符号地址使用 `la.local` 的 PC 相对形式：原 `la` 经 GOT 访问时，第二个路径指针在极简 ELF 中读成 0，曾导致 EFAULT；此修改只影响测试程序，不改变内核装载器契约。

## 验证

| 检查项 | 命令 | 结果 |
|---|---|---|
| LoongArch exec | `make ARCH=loongarch64 test-la-exec RUN_ID=20261015-la-exec-final` | PASS：`LA_EXEC_PASS`、`LA_USER_EXIT_PASS code=0` |
| LoongArch 进程回归 | `make ARCH=loongarch64 test-la-process RUN_ID=20261015-la-exec-regress` | PASS：fork/COW/exit/wait4 |
| RISC-V 进程/exec 回归 | `make ARCH=riscv64 test-process RUN_ID=20261015-la-exec-rv-regress` | PASS：task 0 最终退出码 7 |

上述命令均在 `zhouzhouyi/os-contest:20260510` 中执行。首次 QEMU 测试因测试程序地址生成为 0 而失败；改用 `la.local` 后该失败消失，未观察到新增失败。高地址 LoongArch 用户栈、时钟抢占与完整 FD ABI 仍未覆盖。

## 收口检查

栈顶仍由架构常量单一提供，exec 不新增第二份布局真相；task 的空间 owner 未变化。没有扩大对外 ABI 或放宽 oracle；`la-exec-test` 仅选择首个用户 ELF。现存低地址栈是已有临时布局，需在高地址页表问题解决后移除。
