# M2.8：COW 物理帧失败注入和重复回收验收

- 日期：2026-10-14
- 分类：Patch；测试专用 feature 与 make 目标，不改变生产系统调用 ABI
- 验证者：agent-run
- 环境：比赛镜像 `zhouzhouyi/os-contest:20260510`；QEMU RISC-V virt，4 harts、1024 MiB，任务仍只在 bootstrap hart 执行。

## 目标与方法

`m28-frame-fault-test` 仅在 `make test-cow-oom` 打开。帧分配器在成功分配指定次数后，对下一次申请返回一次 `OutOfMemory`。测试先用实际地址空间复制测出分配点数，再逐点注入，逐次核对：失败结果、父页表映射和 COW 集合未变化、已分配帧数及共享引用登记恢复。测试夹具同时包含只读代码页、跨页可写数据区和用户栈。

首任务注册后，还对完整 `fork_current` 的前 9 个申请点注入故障，覆盖内核栈及子页表，检查返回 `-ENOMEM`、任务槽/就绪队列未发布子任务、父栈页未进入 COW。跨页内核写入在第二页 COW 分配失败时，检查两页用户字节均未半写；重试后父子数据隔离仍正确。

用户程序重复 fork/exit/wait 128 轮。日志验收同时检查每轮物理帧数稳定，以及真实 COW 复制量（131 次 fork、137 次复制），不只搜索最终 PASS 字串。

## 边界

- M2.8 当前固定范围的父/子/内核 COW 写入、退出回收和物理帧 OOM 清理已运行验证。这里的帧计数与复制次数仅代表该输入，不推出所有工作负载无泄漏。
- 测试只注入物理帧分配失败；内核堆耗尽仍走现有 panic/park 策略。任务 ID 单调递增、任务槽 Vec 长期增长，仍需后续生命周期工作解决。
- 状态写回仍使用项目既有的 `usize` 字段；Linux `wait4` 的 32 位状态 ABI、PID 组语义和选项全集属于后续兼容工作。
- LoongArch 用户态调度/COW 尚未实现，本次运行结果只针对 RISC-V。
