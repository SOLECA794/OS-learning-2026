日期：2026-10-13
依据：V2 总路线 §G6「深入机制」：基础充足时优先 COW。机制与边界正确；固定输入对照
验收；结论能由团队解释。门槛定义（431 行）：实现、反例、资源回收、必要回归、状态记录
均完成。前置：G5 shell（dd660f5 之后，master 当前 HEAD）。

## 方案定案：为什么不用 PTE 打标

RV Sv39 与 LA 页表 PTE **都没有空闲位**（RV PTE 位全占用；LA NR/NX/MAT 等满位），
无法仿 Linux PTE 标记 COW 页。因此采用**软件 COW 集合 `BTreeSet<VirtPageNum>` +
PTE 清写位**：集合与 PTE 同域维护（MemorySet 内），架构无关，RV/LA 双架构通用。
COW 复制由 StorePageFault 驱动，复制后恢复写权限并指向新页。

## 实现

- **`src/arch/riscv64/mm.rs`、`src/arch/loongarch64/mm.rs`**：
  - `PageTableEntry::permissions()` 读回 `PagePermissions{read,write,execute,user,memory_type}`
    （RV memory_type 恒 Normal；LA 从 MAT 位推断）。
  - `flush_tlb()`：RV `sfence.vma zero, zero`；LA `invtlb 0x0,$r0,$r0` + `dbar 0`。
- **`src/kernel/mm/page_table.rs`**：
  - `MapPermission::without(WRITE)`（清写位）。
  - `leaf_info(vpn)` 读回 (ppn, perms, memtype)。
  - `set_leaf_permissions(vpn, perms, memtype)`：改权限保留 ppn（COW 修复后不再走此路径，
    保留在文件；已注释说明勿用于 COW）。
  - **`set_leaf(vpn, ppn, perms, memtype)`**：同时改写叶子 ppn+权限（COW 复制关键）。
  - 私有 `leaf_entry` / `leaf_entry_mut`：沿 walk_existing 语义定位叶子槽（借用检查要点：
    `let entry = &table_ref(table)[index]` 先绑定再 then_some）。
  - `impl From<PagePermissions> for MapPermission`。
- **`src/kernel/mm/frame_allocator.rs`**：COW 引用计数
  `static FRAME_REFS: SpinLock<BTreeMap<usize,usize>>`（仅登记共享页；未登记=独占 refcount 1）。
  `cow_retain(ppn)`（计数+1，首位 or_insert(1)）；`deallocate_cow(ppn)`（登记页 -1，
  归零移除并真正 deallocate；未登记页等价 deallocate）。
- **`src/kernel/mm/memory_set.rs`**：
  - `MemorySet` 增 `cow_pages: BTreeSet<VirtPageNum>`。
  - `dup_cow(&mut self, ...)`（需 &mut：父可写页也同步清写位）：① 可写叶：父 PTE 清写位
    + 登记 + child 共享 + cow_retain；② 已 COW 叶：继续共享 + cow_retain；③ 只读/可执行叶：
    直接共享 PTE 不登记；④ Identity 区域跳过按参数重建内核映射。
  - `handle_cow_store(&mut self, vpn)`：分配新帧 → 整页复制 → **set_leaf 指向新 ppn + 恢复
    写权限** → 移除集合 → 释放旧页引用（deallocate_cow）→ flush_tlb → `[cow] copy` 日志。
  - `cow_contains(vpn)`。
  - 释放路径（rollback 与 unmap_from）中 Frame 页 deallocate 全部换 deallocate_cow（Drop 覆盖）。
- **`src/kernel/task/mod.rs`**：`fork_current()` 改走 `parent.space.dup_cow(...)`（原 dup 全量
  复制路径保留但不再被 fork 使用）；新增 `with_current_space(闭包)`（持 SCHED 锁，任务槽
  None 时返回 None）供 trap 调用；UAPP_ELF 四档 cfg（默认 / uapp-fault-test / uapp-shell /
  uapp-cow，各档互斥 not 排除）。
- **`src/kernel/trap.rs`**：StorePageFault → `handle_store_fault`（bad_address().floor() →
  with_current_space → handle_cow_store；Some(Ok(true)) = 已处理，重试故障指令；否则 fatal）。
  Instruction/LoadPageFault 仍 fatal（COW 不做惰性分配/文件缺页）。LA 侧无 task 模块，
  StorePageFault 一律受控停机（cfg 隔离，COW 用户态 LA 尚未对齐）。
- **验收程序 `user/src/bin/uapp-cow.rs`**（新）：无 std；static BUF: [AtomicU8;4096] 初值 0xAA
  （跨一页）；fork 后父子各 spin_loop 100k 先让对方写（验证隔离）；子写 BUF[2048]=0x22 → C3，
  读 BUF[0]==INIT → C4，exit(5)；父写 BUF[0]=0x11 → C1，读 BUF[2048]==INIT → C2，wait4 → C5，
  exit(0)。syscall 号：write=64 / exit=93 / fork=220 / wait4=260。
- **构建链**：user/Cargo.toml 增 [[bin]] uapp-cow；kernel-project/Cargo.toml 增 feature
  `uapp-cow=[]`；Makefile 增 `USER_COW_ELF`（user 目标一并 cp）、`build-cow`（cargo build
  --features ...,uapp-cow + cp + check-image + echo）、`run-cow`（run_qemu.py 统一入口，
  pattern "C5"）。

## 过程中修掉的真问题

1. **`leaf_entry`/`leaf_entry_mut` 借用检查**：`table_ref(table)[index]` 产生 owned value，
   需 `let entry = &table_ref(table)[index]` 再 then_some(entry)；mut 版
   `then_some(&mut table_mut(table)[index])`。
2. **build-cow 缺 `cp $(CARGO_OUT_DIR)/$(KERNEL_NAME) $(KERNEL_ELF)`**：首跑实测 kernel.elf
   是旧 uapp 模式产物（运行日志显示 task 1 fork、exit 42 等旧行为，字符串无 C3 断言）——
   因为 cargo 增量对 include_bytes! 文件不重编译，且 build-cow 从未 cp 产物。补 cp +
   check-image（同 build 目标结构）。
3. **handle_cow_store 首版只用 set_leaf_permissions（改权限保 PPN）→ 实测 illegal
   instruction pc=0x100a4（反汇编=sd a0,0x38(sp)，store 页）**：PTE 仍指向旧共享页，而旧页
   在 deallocate_cow 后归还分配器；父进程第二次复制释放旧页引用归零后，该帧被重新分配，
   页内代码被破坏 → 用户态执行数据 = illegal instruction。修复：改用 `set_leaf(vpn, dst_ppn,
   writable, memtype)` 同时切新页 + 恢复写权限（分配的新帧必须映射，否则泄漏）。
4. **run-cow 首版误用 `--mode run`**（运行器只有 boot/selftest）：改走统一入口
   `--mode boot --pattern "C5"`。
5. **LA 侧编译**：trap.rs 的 COW 分支引 task 模块而 LA 侧 task 被 cfg 掉 → store fault
   分支与 handle_store_fault 包 `cfg(feature = "arch-riscv64")`，LA 保持受控停机。

## 残留风险（Friction Scan）

- **全量 TLB 刷新**：RV sfence.vma zero,zero / LA invtlb all 单核够用；SMP 后需
  per-vpn 失效 + 跨核 shootdown。
- **LA 侧 COW 仅编译验证**：LA 用户态尚未对齐（StorePageFault 受控停机），实机验证
  排 W9-10。
- **内核态写 COW 页未专门测**：copy_to_user 落到共享页的场景（当前 wait4 wstatus=0 不写
  用户内存）；后续进程/文件接口前补定向用例。
- **FRAME_REFS 持锁开销未测**：BTreeMap 引用计数在 copy 路径持锁，量级未测（性能阶段
  再评估，Safe）。
- **user stack / 代码页也进 COW**：dup_cow 处理 Framed 区全部可写叶（含栈），复制次数
  为 4 的固定输入对照已覆盖；大栈/深调用在性能阶段再议（Euclid）。
- **`let mut start = ppn;`**（frame_allocator deallocate_range）unused_mut warning：
  顺手清理（同批 17 个既有 warning 未全清，均为 unused/unreachable，Safe）。
