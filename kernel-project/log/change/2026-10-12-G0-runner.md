## 实现

- **`tools/run_qemu.py`**（新建，宿主运行器，由 Make 调用）：
  - 校验输入：QEMU 存在、内核 ELF 存在并冻结 SHA-256（`--elf` 可覆盖）。
  - 独立日志目录 `artifacts/runs/<run-id>/`：serial.log / qemu.stderr.log /
    result.json，每次新建、禁止追加旧日志。
  - `subprocess.Popen(..., start_new_session=True, stdin=DEVNULL, bufsize=0)`
    建立独立进程组（不使用 preexec_fn）；select 轮询持续排空 stdout/stderr，
    不阻塞 Guest；超时 TERM → 3s 宽限 → SIGKILL 进程组，孤儿兜底。
  - **有界拼行**（LineAssembler，单行上限 8KiB，超长强制断行防洪泛阻塞）；
    **滚动窗口 pattern 检测**覆盖跨 chunk / 无换行 / 行尾不完整输出。
  - KTEST 事件解析（BEGIN/CASE/END）：未登记结束或未执行的用例不算 PASS。
  - result.json 字段：run_id/mode/arch/version/source(commit)/elf(path+sha256)/
    qemu(version+argv)/time(start+end+elapsed+budget)/exit(code+reason)/
    logs/pattern/ktest/passed。
  - 结束原因分类：MATCHED / NORMAL_EXIT / EXIT_TIMEOUT / TEST_FAILED /
    UNKNOWN；fail_fast 写工具缺失/构建产物缺失结论。
- **`Makefile`**：`test`（boot 模式，默认 20s 预算，期望 M1 标记）与
  `test-fault`（timeout 60 + fatal trap pattern）统一改走运行器；
  新增 `RUN_ID ?= $(shell date +%Y%m%d-%H%M%S)`；删除旧 test（run-test.sh）目标；
  `artifacts/` 入 .gitignore（保留目录，make clean 不删除）。
- **`docs/10-testing-and-validation.md`**：§1 增运行器统一入口说明。

## 过程中修掉的真问题

1. **无换行输出检测缺失**（宿主自测发现）：fatal trap 等内核尾行常无结尾 \n，
   完整行检测永不触发。加滚动窗口检测（scan_tail 增量 + 窗口截尾）。
2. **跨 chunk pattern 漏检**（make test-fault 实机复现，fault-20261012-214719）：
   serial 输出跨多次 read，单 chunk 搜索不中 → 误判 EXIT_TIMEOUT。滚动窗口
   同时覆盖此场景，修复后 test-fault PASS。
3. **Makefile test 目标重复**（首跑 `make test` 仍走旧 run-test.sh）：旧目标
   在文件末尾定义覆盖新目标，删除旧目标（注释亦清）。

## 验证矩阵（agent-run，WSL Ubuntu-24.04 + QEMU 8.2.2）

- **宿主自测**（/tmp/fake_qemu.sh，可控子进程）5 场景全过：
  normal → PASS(MATCHED)；no-newline → PASS（滚动窗口）；flood → PASS
  （洪泛不阻塞）；hang → FAIL(EXIT_TIMEOUT)；ignores-term → PASS
  （SIGKILL 兜底，rc=-9，无孤儿进程残留：ps 无 sleep 残留）。
- `make test`（RV boot）：PASS，reason=MATCHED，qemu rc=0，
  result.json 字段完整（elf sha256=56064ea003bb…，QEMU 8.2.2，argv 逐项）。
- `make test-fault`（迁移后）：PASS，reason=MATCHED，
  elf sha256=ba76f6c186c0（uapp-fault-test 模式），rc=0。
- 滚动窗口修复后 make test 回归 PASS（无回归）。

## 残留风险（Friction Scan）

- **QEMU 因 stdin=DEVNULL 收到 EOF 自行退出**（rc=0 而非 -15）：mon:stdio
  模式下 QEMU 见 stdin EOF 即退，内核停驻语义靠 MATCHED 判定收束；
  不影响结果真实性，但"内核仍驻留"的观察窗口比 run 短。后续若需要
  长驻观察（如定时器稳定性），可给运行器模式追加 -serial stdio 或
  保留 stdin 的 pipe。
- **KTEST 事件尚无内核侧输出**（G0 阶段无 selftest）：运行器协议已就绪，
  首个 KUnit 式自检（docs/10 §2）落地时消费。
- **洪泛上限 8KiB/行**：超过即断行截断（防阻塞），极端情况 pattern 若
  恰在截断点会被切分——滚动窗口按 8KiB+pattern 长度截尾，已覆盖常规。
- **elapsed 为 wall-clock**：宿主负载不影响判定（deadline 同样 wall-clock），
  预算口径与 V2 一致。
