# 00 · 定位设计（Vision）

本文档定义项目存在的理由、目标边界与成功标准。所有设计决策必须能追溯到这里的某一条。

## 1. 项目愿景

构建一个 **从 0 自研、系统调用兼容 Linux、支持 RISC-V64 与 LoongArch64 双架构的 Rust 宏内核**。目标按竞赛阶段分层管理：

- **区域赛阶段（近期主线）**：一个完整、可教学、可演示的小型内核作品——用户程序能安全进入内核、被调度、访问文件并正常退出，资源管理正确，配齐测试与教学材料。
- **国赛阶段（后续扩展）**：在稳定功能基线上扩展 Linux ABI 兼容广度、文件系统、网络、SMP、实板与性能（BuildStorm），冲击一等奖水准。

> **可证伪标记**：本分层依据 2026 赛道一等奖溯源（§6）与 2025 华东 OS 原理赛官方规则（代码 30% / 文档 30% / 教学 10% / 工程 10% / 演示答辩 20%，且未列出双架构、ext4、固定 QEMU、完整 Linux 测例等硬性要求）。**评测规则或官方章程变更时，须按正式文件重估本分层，不得把历史情报当成本届公理。**

## 2. 目标（Goals）

### 2.1 区域赛阶段（近期必达）

1. **用户态闭环**：RV 静态 ELF 用户程序进入内核、执行最小 syscall（write/read/exit）、安全返回；非法访问受控处理。
2. **进程与调度**：上下文切换、用户态时钟抢占（RR）、eager fork、exec、exit/wait；父子隔离与资源回收正确。
3. **文件与交互**：VFS/FD、ramfs、命名程序集合、控制台输入、小 shell。
4. **测试与教学**：自动回归入口（超时/退出码/原始日志）、当前状态表、3–5 个可复现教学实验、设计报告与答辩材料。
5. **一个深入主题**：推荐 COW（仅在普通 fork、页权限、TLB 处理、回收稳定后进入）；懒分配为独立主题，不与 COW 打包承诺。

### 2.2 国赛阶段（后续扩展，非近期成功标准）

6. **双架构完整运行**：RISC-V64 与 LoongArch64 在 QEMU 与实板（VisionFive2 / 龙芯 2K1000）上可运行测试套件。
7. **Linux syscall 兼容面广且正确**：以 LTP 等测例为验收驱动，覆盖进程、信号、文件系统、内存映射、网络（TCP）、时钟等主流系统调用；errno 与语义对齐 Linux UAPI。
8. **性能达标**：BuildStorm（系统内构建工具链）成绩不劣于官方 Linux 基线；优化基于 profile 证据，而非猜测。
9. **完全自研**：内核主体全部为团队自研代码，可公开陈述"从 0 构建"；外部依赖仅限基础设施 crate，全部声明与评审。
10. **工程可复现**：一键构建（离线依赖）、CI 双架构回归、证据日志可复现（SHA-256 身份）。

## 3. 非目标（Non-Goals，明确不做）

- 不做微内核 / 混合内核形态切换。
- 区域赛阶段不承诺：完整 ext4、完整 TCP/IP、广泛 glibc/LTP、用户线程与复杂信号、内核抢占、异步 SMP、实板、KVM、SSH、BuildStorm 性能。
- 不复制 Linux 或任何开源内核的内部对象模型；参考仅限 ABI 语义与设计思路。
- 不做开发时间排期（本文档不含时间计划，排期属团队项目管理范畴）。
- 不引入 smoltcp 等完整第三方协议栈作为最终交付（网络自研路线见 docs/06-networking.md）；若暂借，必须带退出条件。
- 双架构为既成约束：**持续维护，但不要求每个新功能双架构同时完成**；用户态功能按"主线先行、适配阶段跟进"推进（见 docs/08）。

## 4. 成功标准（可验证）

### 4.1 区域赛验收

| 维度 | 标准 |
|---|---|
| 功能 | 用户程序进入 → 被调度 → 访问文件 → 退出 → 资源完整回收的链路在 RV 上稳定运行；非法访问受控处理 |
| 文档 | 设计依据、模块实现、测试与限制记录完整；能力状态表如实（区分运行验证/编译验证/未运行） |
| 教学 | 3–5 个可复现实验，覆盖用户态进入、页权限、时钟抢占、fork/COW、FD 语义 |
| 工程 | 干净环境可复现构建与运行；证据绑定 commit、产物 SHA、工具链、QEMU 参数 |
| 演示 | 启动进入小 shell、运行外部程序、展示隔离与回收 |

### 4.2 国赛验收（后续阶段）

| 维度 | 标准 |
|---|---|
| 功能 | CAgent 双架构通过率达到一等奖水平（参考：一等奖 199-200/200 或同档） |
| 性能 | BuildStorm 双架构不劣于官方 Linux 基线（参考：一等奖 RyOS RV 1534s / LA 1390s vs 基线 1616s / 1985s） |
| 原创 | 内核主体 100% 团队自研；git 历史无外部 OS 代码导入提交 |
| 工程 | `make all` 从干净环境可复现构建；`sha256sum -c` 校验证据日志 |
| 答辩 | 设计文档 + AI 使用声明 + 独门亮点演示（KVM / 自研网络栈 / 内核 SSH 三选一） |

> **状态分级义务**：README 状态表必须区分「已实现且运行验证 / 已实现但仅编译验证 / 尚未运行 / 已知限制 / 后续计划」。旧版本成功记录不得覆盖新版本结论；未运行项明确标 `not-run`。

## 5. 设计原则（一切文档与代码的裁判）

1. **兼容性优先于内部优雅**：syscall 对外语义以 Linux UAPI 为准；内部结构可自行设计，但外部行为不得"自作主张"。
2. **单一真相源**：同一事实只允许一个 owner 保存（见 AGENTS.md 代码形状约束）。
3. **证据驱动**：性能与正确性结论必须来自可复现实验，禁止"感觉对"。
4. **双架构同源**：共享逻辑写一次，架构差异收敛在 arch 层；双架构持续编译回归；用户态功能按"主线先行、适配阶段跟进"推进，不强制每个新功能同时双架构完成。
5. **最小依赖**：能用自研解决的不用第三方；第三方 crate 必须评审、固定版本、离线 vendored。
6. **验收前置**：任何子系统开工前明确验收标准（Implementation Boundary），否则不做。

## 6. 竞品对标（为什么这个定位能赢）

2026 赛道一等奖全部为宏内核/类 UNIX 兼容路线：KernelX（自研宏内核）、Anemone（完全自研）、RyOS（继承重写）、Kairix（多核宏内核）、MossOS（组件化+兼容面）、CosmOS（rCore 扩展）。本项目的差异化：**完全自研 + 兼容面广度 + 性能证据 + 一个独门亮点**，与一等奖路线一致。

> **可证伪标记**：上述"一等奖公式"是历史样本的共性归纳，证明该路线可行，**不构成获奖承诺**；区域赛评分以官方章程为准（见 §1）。参考项目的功能数量、代码行数与作者自述奖项不得当作官方获奖门槛。
