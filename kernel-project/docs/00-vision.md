# 00 · 定位设计（Vision）

本文档定义项目存在的理由、目标边界与成功标准。所有设计决策必须能追溯到这里的某一条。

## 1. 项目愿景

构建一个 **从 0 自研、系统调用兼容 Linux、支持 RISC-V64 与 LoongArch64 双架构的宏内核**，达到操作系统大赛内核实现赛道一等奖水准：CAgent 功能测例高分通过、BuildStorm 性能追平或超越官方 Linux 基线、具备可演示的独门能力。

## 2. 目标（Goals）

1. **双架构完整运行**：RISC-V64 与 LoongArch64 均在 QEMU 与实板（VisionFive2 / 龙芯 2K1000）上可启动、可运行测试套件。
2. **Linux syscall 兼容面广且正确**：以 LTP 等测例为验收驱动，覆盖进程、信号、文件系统、内存映射、网络（TCP）、时钟等主流系统调用；errno 与语义对齐 Linux UAPI。
3. **性能达标**：BuildStorm（系统内构建工具链）成绩不劣于官方 Linux 基线；优化基于 profile 证据，而非猜测。
4. **完全自研**：内核主体全部为团队自研代码，可公开陈述"从 0 构建"；外部依赖仅限基础设施 crate，全部声明与评审。
5. **工程可复现**：一键构建（离线依赖）、CI 双架构回归、证据日志可复现（SHA-256 身份）。

## 3. 非目标（Non-Goals，明确不做）

- 不做微内核 / 混合内核形态切换。
- 不追求完整 Linux 兼容（如全部 400+ syscall、完整 cgroup/namespace 等不在首期范围）；兼容优先级由测例分数驱动。
- 不复制 Linux 或任何开源内核的内部对象模型；参考仅限 ABI 语义与设计思路。
- 不做开发时间排期（本文档不含时间计划，排期属团队项目管理范畴）。
- 不引入 smoltcp 等完整第三方协议栈作为最终交付（网络自研路线见 docs/06-networking.md）；若暂借，必须带退出条件。

## 4. 成功标准（可验证）

| 维度 | 标准 |
|---|---|
| 功能 | CAgent 双架构通过率达到一等奖水平（参考：一等奖为 199-200/200 或同档） |
| 性能 | BuildStorm 双架构不劣于官方 Linux 基线（参考：一等奖 RyOS RV 1534s / LA 1390s vs 基线 1616s / 1985s） |
| 原创 | 内核主体 100% 团队自研；git 历史无外部 OS 代码导入提交 |
| 工程 | `make all` 从干净环境可复现构建；`sha256sum -c` 校验证据日志 |
| 答辩 | 设计文档 + AI 使用声明 + 独门亮点演示（KVM / 自研网络栈 / 内核 SSH 三选一） |

## 5. 设计原则（一切文档与代码的裁判）

1. **兼容性优先于内部优雅**：syscall 对外语义以 Linux UAPI 为准；内部结构可自行设计，但外部行为不得"自作主张"。
2. **单一真相源**：同一事实只允许一个 owner 保存（见 AGENTS.md 代码形状约束）。
3. **证据驱动**：性能与正确性结论必须来自可复现实验，禁止"感觉对"。
4. **双架构同源**：共享逻辑写一次，架构差异收敛在 arch 层；禁止复制两份实现。
5. **最小依赖**：能用自研解决的不用第三方；第三方 crate 必须评审、固定版本、离线 vendored。
6. **验收前置**：任何子系统开工前明确验收标准（Implementation Boundary），否则不做。

## 6. 竞品对标（为什么这个定位能赢）

2026 赛道一等奖全部为宏内核/类 UNIX 兼容路线：KernelX（自研宏内核）、Anemone（完全自研）、RyOS（继承重写）、Kairix（多核宏内核）、MossOS（组件化+兼容面）、CosmOS（rCore 扩展）。本项目的差异化：**完全自研 + 兼容面广度 + 性能证据 + 一个独门亮点**，与一等奖公式一致。
