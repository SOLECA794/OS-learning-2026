# 10 · 测试与验证策略

## 1. 分层测试

| 层 | 内容 | 运行位置 | 门槛 |
|---|---|---|---|
| 单元测试 | 纯逻辑（容器、解析、分配器） | cargo test（host） | 必过 |
| 内核内测试 | 内核自检（KUnit 式，feature 门控） | QEMU（feature=kunit） | M1 后必过 |
| 用户态测试 | 自研测试程序 | QEMU 内 init 启动 | 每 syscall/模块对应 |
| LTP 集成 | LTP 子测例（分数驱动） | QEMU + 测试盘 | 分数台账 |
| 性能基准 | fork/syscall 延迟/fs 吞吐/BuildStorm | 专用机/长跑 | 证据记录 |
| 实板验证 | VF2 / 2K1000 | 实机 | M4 阶段 |

## 2. 内核自检（KUnit 式）约定

- 测试挂在与被测语义相同的模块末尾（feature 门控的内联测试模块），不默认新建全局测试文件。
- 涉及调度/锁/等待/时间的内核测试，使用生产生命周期与显式 phase/predicate/Event/token 闭合，禁止用固定 yield / sleep / tick 次数模拟 happens-before。
- 除框架本身外，不为一组测试新建测试支持模块；跨子模块组合测试放最低共同 owner 的 mod.rs。

## 3. LTP 驱动策略（分数优先）

- 评分口径：一个 TPASS 算一分；优先实现子测例多的测试族（先进程族、再文件、信号、内存、网络）。
- 用 profile 选择测试组合：ltp/profile.txt 可裁剪，针对性执行/跳过。
- 失败处理：按 sdd-governance/skills/debug/SKILL.md 渐进式调试（浅层索引 → 小批代表 → 失败集 diff），禁止逐条硬啃或 case hacking。
- 输出解释：PASS / FAIL / TCONF / BROK 分类管理；TCONF 不计分，BROK 需查明原因。

## 4. 验证伦理（强制）

- 区分 agent-run / user-run / not-run 并如实标注；静态检查不等于运行验证。
- 性能结论必须：固定拓扑 + 输入身份（SHA-256）+ 口径说明（见 evidence skill 的双分母规则）。
- 每个子系统验收标准见对应设计文档；未达标准不得宣称完成。

## 5. 回归集

- 每合并一个功能，跑最小相关回归集（该子系统既有测例 + 相邻子系统冒烟）。
- 每周全量回归：双架构编译 + 基础测试 + 分数台账更新。
- 回归失败即阻止合并；多个不同观感失败一起消失时合并失败族（反向归并）。

## 6. 性能基准台账

| 基准 | 测什么 | 参考目标 |
|---|---|---|
| fork 循环 | 进程创建热路径 | 与 Linux 基线对比（证据记录） |
| syscall 延迟（getpid） | 陷入/返回开销 | 一等奖做法：测延迟上界 |
| 小文件 open/read | 编译负载文件访问 | 对比 Linux 基线 |
| 大文件顺序读 | 页缓存/块路径 | 对比 Linux 基线 |
| loopback 吞吐 | 网络路径 | netperf 类脚本 |
| SMP 加速比 | 多核伸缩 | 参考一等奖 8核/单核 1.67-1.68 倍 |

每个基准：脚本入库（tools/bench/）、输出带 SHA-256、A/B 结论必须同条件可比。
