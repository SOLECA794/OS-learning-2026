# 09 · 编码规范

适用于全部 Rust 代码（内核、工具、测试）。AI agent 与人类开发者同样遵守；违反以下规则属于评审问题而非风格建议。

## 1. 结构约束（内核代码）

- **单一真相源**：不缓存能从 owning object 推导的字段。仅当性能 / 稳定 snapshot / 跨生命周期诊断三类需求成立时才允许派生字段，字段旁必须说明真相源与是否允许 stale。
- **状态所有权唯一**：一个状态转换只由一个 owner 负责。其它结构持有 token / handle / 弱引用，禁止双重语义（"task 里一份、辅助对象里又一份"）。
- **窄接口优先**：下层只需要唤醒能力 / 文件能力 / 任务身份时，不要传完整 Task / File / 私有锁。定义窄 ctx / token / owner API。
- **诊断字段显式标注**：只用于日志/排障的字段标注"不参与行为决策"；纯诊断字段不得反向驱动状态机。
- **断言策略**：正确性不变量的轻量检查用 `assert!`；`debug_assert!` 只用于昂贵扫描或 release 不能承受的检查。cleanup/Drop 路径先退订、释放、撤销发布再用断言。
- **临时桥必须带退出条件**：为阶段迁移/LTP 兼容/ABI 缺口引入的临时字段、fallback、兼容 wrapper，必须注明保留原因、行为边界、移除条件。

## 2. 命名

- 类型/函数命名直接表达语义，禁用无区分度词汇（Value/Data/Manager/State/utils/misc 等）作为类型名后缀。
- syscall 分类文件命名：fs.rs / mm.rs / task.rs（与 Linux 语义对应）。
- feature gate 命名：kebab-case，与 Cargo feature 一致。

## 3. 错误处理

- 内部不变量违规用 `assert!`（fail-fast）；对外可恢复错误走 Result 并映射正确 errno。
- ABI 已规定的资源耗尽 / 容量背压等可恢复结果必须按契约返回，不得偷换为 panic。
- 不可睡眠上下文（IRQ/IRQ-off）允许适度有界内核堆分配，失败 panic 可接受；不得为形式上的可恢复性机械增加错误分支。

## 4. 注释要求（必须注释的情形）

- 不明显的约束、不变量、状态机转换、锁顺序、生命周期、唤醒/取消顺序。
- Linux/POSIX ABI 选择、errno 区别、flag 兼容性、静默兼容、故意不支持的特性。
- 临时兼容桥、已接受限制、回退路径、后续阶段必须消失的代码。
- 注释解释"为何如此设计、依赖什么不变量、何时可改/删"，不重复代码表面；禁止叙事填充。

## 5. 用户态与外部接口

- 用户指针经统一安全访问层（uptr/ubuf）校验，禁止直接解引用裸指针。
- Linux ABI 表示只允许出现在 syscall/兼容边界，进入核心子系统前转换为内部领域类型。
- 用户态测试程序：自包含、输出可 grep、失败路径明确（`PASS`/`FAIL` 标记）。

## 6. 格式化与静态检查

- 全库 `cargo fmt` 统一格式；格式化器产生的无关改动仅在维护风格一致性时可接受。
- `cargo clippy`（若纳入 CI）警告不豁免，除非注释说明理由。
- 禁止提交未使用 import / 死代码（自己引入的必须删除）。

## 7. 架构差异

- 双架构共享逻辑写一次；差异收敛在 `src/arch/`。
- 跨架构改动必须同时检查 riscv64 与 loongarch64 实现，禁止单架构提交（除非显式标注为暂缓项并记录）。
